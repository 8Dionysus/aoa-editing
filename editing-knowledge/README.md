# Editing knowledge

`scenarios/` contains checked-in candidate scenario packets used to document the
three executable planner lanes. `candidates/` is the current review surface for
techniques extracted from passing runtime evidence. `history/` preserves the
exact superseded packet bytes needed to reproduce an upgrade; it is not a second
current source.

All files validate as `TechniquePacket`. A packet is operational guidance, not
project authority. Runtime Treatments and approved Decision Graphs own an edit;
Tree of Sophia owns any future canon. One success cannot promote a packet beyond
candidate. Transfer adds application history and still requires human review.

`scenarios/screen.workflow.json` revision 3 admits reviewed operator experience
from a real human-free Codex workflow as one failed and one warning application,
without retaining source paths, hashes, transcript text, or private project
identity. Its executable core is source-contiguous speed tiers, real-time prompt
entry, natural live holds, and typed live UI regions. Region-aware temporal
loops and automatic resource-aware final segmentation remain promotion
questions rather than claimed capabilities.

`candidates/continuous-contain-reveal.json` is revision 4 of the first extracted
candidate. Its checked-in bytes equal the heterogeneous transfer-v2 evaluator
output. The packet retains a normalized dense C1 similarity trajectory,
phase/coupling semantics, a fixed-pivot gauge, and an effective-upscale guard,
but retains no media hash or physical owner path. Its application history
records the two earlier cases plus five passing heterogeneous transfers and two
typed contraindications.

`history/continuous-contain-reveal-v1-revision2.json` is the exact revision-2
input from which transfer v2 derives the portable revision-3 recipe. Revision 4
intentionally remains `candidate`: passing a seven-case corpus is transfer
evidence, not authorization to promote into Tree of Editing canon.
